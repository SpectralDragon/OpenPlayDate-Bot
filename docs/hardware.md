# Подключение и диагностика

## Подключение

Если кнопки не работают, команда `s` в Serial Monitor показывает состояния A, B и кнопки джойстика: `1` — отпущена, `0` — нажата. Команда `c` включает вывод изменений этих уровней, повторная `c` отключает его. Принятые программой нажатия отмечаются строками `PRESS`. Если при нажатии уровень остаётся `1`, проверь провод сигнала и соединение с GND; если постоянно `0`, проверь, не выбраны ли два постоянно соединённых вывода кнопки.

Сохраняем подключение из [нашей схемы](wiring/ai-s3-wiring.svg).

| Экран | AI-S3 |
| --- | --- |
| VCC | 5Vin только после проверки выхода питания: см. IN-OUT ниже (J1 экрана разомкнута) |
| GND | GND |
| CS | GPIO10 |
| RESET | GPIO14 |
| DC | GPIO9 |
| SDI / MOSI | GPIO11 |
| SCK | GPIO12 |
| LED | 3V3 |

Джойстик: GND → GND, «+5V» → **3V3**, VRx → GPIO4, VRy → GPIO5, SW → GPIO6.
Кнопки A и B замыкают соответственно GPIO7 и GPIO15 на GND. Подтяжки включены программно.
Тач и SD пока не подключены. GPIO35–37 оставляем для памяти PSRAM.
SDO(MISO) экрана можно подключить к GPIO13 для диагностики; именно этот дополнительный провод был подключён при проверке контроллера. Для вывода картинки он не обязателен. T_DO относится к тачу и для этой проверки не используется.
Переставляй провода при отключённом USB. На сигнальные контакты ESP32 нельзя подавать 5 В.

### Питание экрана: особенность 5Vin и IN-OUT

На нашей AI-S3 контакт подписан **5Vin**. До исправления питания при USB-подключении на нём измерено около **0,48 В**, а на LED экрана — около **3,2 В**. На исходной фотографии площадки **IN-OUT** рядом с белым RGB-светодиодом разомкнуты. Предыдущая версия схемы ошибочно предполагала наличие 5 В на этом контакте сразу после подключения USB.

В [схеме близкой платы YD-ESP32-S3 V1.4 от производителя](https://github.com/vcc-gnd/YD-ESP32-S3/blob/main/5-public-YD-ESP32-S3-Hardware%20info/YD-ESP32-S3-SCH-V1.4.pdf) диод D3 пропускает питание с контакта 5V внутрь платы, а перемычка IN-OUT шунтирует его для выдачи питания наружу. Наша AI-S3 — другая версия платы; совпадение площадок и измерений указывает на такое же устройство цепи. После работы с IN-OUT пользователь подтвердил, что всё работает (17 октября 2026).

Перед пайкой отключают USB и все внешние источники питания. Проверка площадок при отключённом питании: одна сторона IN-OUT должна иметь прямую связь с 5Vin. Замыкание подтверждённой перемычки IN-OUT выполняется пайкой; это перемычка **фиолетовой AI-S3**, а **J1 красного экрана оставляют разомкнутой**. После изменения сначала измеряют напряжение 5Vin относительно GND без подключённого экрана. VCC экрана подключают к этому выводу только после подтверждения примерно 5 В.

Аппаратный ID контроллера прочитать не удалось ни через отдельный SDO, ни через общую SDA/MOSI. Профиль ST7789 выбран по геометрическому тесту: все четыре угловые отметки видны у физических углов экрана. На фотографии теста с инверсией и RGB поле WHITE было чёрным, RED — жёлтым, GREEN — пурпурным, BLUE — голубым. Поэтому в текущей настройке отключена инверсия и выбран BGR. Пользователь подтвердил работающие глазки после исправления цветов.
Если после успешной прошивки экран белый, проверь питание, CS/DC/RESET/MOSI/SCK и маркировку контроллера.
Для проводов на макетке SPI настроен на щадящую частоту 10 МГц в `include/tft_setup.h`.
В Serial Monitor отправь `t`: появятся красная, зелёная и синяя полосы с белым полем и надписью.
Этот тест рисует прямо на экран, без буфера анимации. Команда `e` возвращает глазки; перезапуск тоже возвращает обычный режим.
Команда `s` печатает выбранный драйвер, размер экрана и состояние программы. В обычном режиме ожидается `ready=1 test=0 configured_driver=7789 size=320x240`.
Сообщение `ready=1` подтверждает запуск программы и выделение памяти, но само по себе не подтверждает картинку и модель контроллера.

Чтобы полосы показывались при каждом включении, прошей диагностическое окружение:

```powershell
.\tools\pio.ps1 run --environment display-test --target upload --upload-port COM5
```

Для возврата обычного запуска глазок: `.\tools\pio.ps1 run --environment robot-eyes --target upload --upload-port COM5`.
Если экран совсем не светится, проверь измерением напряжения VCC–GND и LED–GND. При перестановке проводов отключай USB. Для VCC требуется проверенный выход примерно 5 В; контакт 5Vin без проверки IN-OUT таким выходом считать нельзя. Подсветка не управляется программой.

### Диагностика искажённого изображения

Для диагностики доступны два независимых окружения:

```powershell
.\tools\pio.ps1 run --environment display-id --target upload --upload-port COM6
.\tools\pio.ps1 run --environment display-soft-test --target upload --upload-port COM6
```

Укажи актуальный порт платы вместо COM6. `display-id` использует медленный программный SPI без библиотеки экрана. Подключи SDO(MISO) → GPIO13 при выключенном USB, затем после прошивки отправь `i` через монитор. В выводе есть чтение с подтяжкой вверх и вниз: если оно меняется с одних нулей на одни FF, линия ответа не управляется экраном и определить контроллер по такому ответу нельзя. Именно такой результат получен при первой проверке.

`display-soft-test` использует Adafruit ILI9341 с программным SPI и выводит три сплошные полосы с надписью SOFTWARE SPI TEST. Он исключает буфер анимации, TFT_eSPI и аппаратный SPI ESP32-S3 из пути рисования, но всё ещё предполагает контроллер ILI9341. Качество картинки проверяется визуально.

Тест `display-soft-test` показывал читаемый текст и шум внизу. `display-test-ili9488` (480×320, SPI 1 МГц) убрал шум, однако цвета и геометрия на следующих фото были неправильными. `display-test-st7789` использует текущий профиль 320×240 на частоте 1 МГц. При проверке цифры 1–4 должны находиться у четырёх физических углов, красная/зелёная/синяя полосы — соответствовать своим подписям, а нижнее поле быть белым с чёрной надписью.
