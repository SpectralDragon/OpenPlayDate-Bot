# OpenPlay Lua API 1

Свою игру или программу робота можно написать на Lua, собрать в один `.opd`,
загрузить через Wi-Fi и запустить из **Lua-программы** на консоли.
Это собственный API OpenPlay: программы Playdate SDK и бандлы `.pdx` напрямую
не совместимы. В прошивку включена Lua **5.4.9** с 64-битными целыми и `double`.

## Первая игра

Готовые примеры лежат в `examples/bouncing-ball` и `examples/robot-ports`.
Для упаковки нужен только Python 3. Создай бандлы вне папок с исходниками:

```powershell
python tools/opd.py pack examples/bouncing-ball .pio/examples/bouncing-ball.opd
python tools/opd.py pack examples/robot-ports .pio/examples/robot-ports.opd
python tools/opd.py inspect .pio/examples/bouncing-ball.opd
```

Открой на консоли **Lua-программы → Добавить программу**, подключись к показанной
сети Wi-Fi и открой `http://192.168.4.1/`. В разделе **Lua-программы** загрузи `.opd`.
Нажми B на консоли и выбери файл. Имя `.opd`: 1–40 символов `a-z`, `0-9`, `_`, `-`.
При загрузке файл проверяется перед заменой предыдущей версии с тем же именем.
Загрузка не запускает Lua-код; синтаксис и выполнение проверяются при запуске.

Джойстик, A и B передаются приложению. Удержание кнопки джойстика **0,7 секунды**
открывает системную паузу; из неё можно продолжить или закрыть приложение.
Первое нажатие A при запуске и кнопки при выходе из паузы не передаются, пока
они не отпущены. Автоматического перехода к глазкам во время работы или паузы нет.

## Папка программы и манифест

```text
my-game/
  manifest.json
  main.lua
  ball.lua
  assets/
    hint.txt
    picture.opi
```

```json
{
  "api": 1,
  "id": "my-game",
  "name": "Моя игра",
  "kind": "game",
  "entry": "main.lua",
  "fps": 30
}
```

| Поле | Значение |
| --- | --- |
| `api` | Обязательное целое `1`; другие версии отклоняются |
| `id` | Обязательное имя из 1–40 символов `a-z`, `0-9`, `_`, `-` |
| `name` | Обязательное название UTF-8 до 80 байт, без управляющих символов |
| `kind` | Обязательное `game` или `robot` |
| `entry` | Обязательный путь к Lua-файлу внутри бандла |
| `fps` | Целевая частота 1–60, по умолчанию 30; реальная зависит от нагрузки и экрана |
| `permissions` | Доступ к портам; пример ниже. По умолчанию порты не выделяются |

Упаковщик добавляет все обычные файлы и вложенные папки, кроме корневого
`manifest.json` и скрытых файлов/папок. Символические ссылки отклоняются.
Пути чувствительны к регистру: латинские буквы, цифры, `_`, `-`, `.`, `/`;
до 96 байт. Абсолютные пути, `..`, `.`, обратные слеши, пустые части пути и
повторные пути запрещены. Lua-файлы должны иметь расширение `.lua`.

## Жизненный цикл

Главный файл возвращает таблицу. Все обработчики необязательны; если поле задано,
оно должно быть функцией. Обработчики вызываются без `self`:

```lua
local g = opd.graphics
local x = 20

return {
    init = function()
        -- Один раз после выполнения главного Lua-файла.
    end,

    update = function(dt)
        -- dt в секундах: фактически прошедшее время, не больше 0.25.
        x = (x + 60 * dt) % opd.width
        if opd.input.pressed("b") then opd.system.exit() end
    end,

    draw = function()
        g.clear(0)
        g.color(g.rgb(255, 211, 77))
        g.fillCircle(math.floor(x), 120, 10)
        g.text("Привет!", 14, 14)
    end,

    pause = function()
        -- Перед освобождением GPIO/UART и показом системной паузы.
    end,

    resume = function()
        -- После паузы: заново настрой нужные GPIO и открой UART.
    end,

    shutdown = function()
        -- При обычном закрытии, включая закрытие из паузы.
        -- Если программа была на паузе, GPIO/UART уже недоступны.
    end
}
```

Порядок: главный файл → `init` → повторение `update(dt)` / `draw` → вывод кадра.
Перерисовка всего экрана происходит после `draw`; буфер сохраняется между кадрами.
Пропущенные кадры не догоняются. Во время паузы `update` и `draw` не вызываются;
после продолжения `dt` начинает отсчитываться заново.

`opd.system.exit()` запрашивает выход после возврата текущего обработчика.
При ошибке приложение закрывается, порты освобождаются, появляется экран ошибки;
`shutdown` после аварии не вызывается. Полное сообщение, до 240 байт, доступно
в USB-журнале с префиксом `LUA ERROR`.

## Общие функции

| Функция или поле | Результат |
| --- | --- |
| `opd.apiVersion` | `1` |
| `opd.width`, `opd.height` | `320`, `240` |
| `opd.system.millis()` | Миллисекунды с запуска платы; 32-битный счётчик оборачивается примерно через 49,7 дня |
| `opd.system.exit()` | Запросить закрытие |
| `opd.system.log(text)` | Строка в USB-журнал: до 256 байт за вызов, суммарно до 512 за обработчик. Если буфер USB занят, сообщение пропускается |
| `opd.assets.read(path)` | Содержимое файла бандла как бинарная Lua-строка, до 64 КиБ |
| `require("ball")` | Загрузить `ball.lua` от корня бандла |
| `require("lib.ball")` | Загрузить `lib/ball.lua` |

`require` кеширует результат отдельно для каждого запуска. Если модуль возвращает
`nil`, результатом становится `true`. Циклические зависимости вызывают ошибку.
Поиска во внешних папках, `init.lua` и нативных библиотек нет.
Ассеты доступны только для чтения, не извлекаются в общую файловую систему.
Текущая версия не предоставляет сохранение пользовательских данных.

## Кнопки и джойстик

| Вызов | Результат |
| --- | --- |
| `opd.input.down(button)` | `true`, пока кнопка удерживается |
| `opd.input.pressed(button)` | Было нажатие с предыдущего кадра |
| `opd.input.released(button)` | Было отпускание с предыдущего кадра |
| `opd.input.axis("x")`, `opd.input.axis("y")` | Ось джойстика от −1 до +1; вправо и вниз — положительное направление |

Имена кнопок: `a`, `b`, `stick`, `left`, `right`, `up`, `down`.
Направления считаются нажатиями за порогом 0,55. Короткие нажатия между кадрами
накапливаются: `pressed` и `released` могут одновременно быть `true`.
Чтение состояния не сбрасывает событие; оно видно и в `update`, и в `draw`
текущего кадра. Удержание `stick` также обслуживается системной паузой.

## Графика

Координаты целочисленные, начало слева сверху. Цвет — RGB565 (0–65535),
по умолчанию белый. Отрисовка за пределами экрана обрезается.

| `opd.graphics.*` | Действие |
| --- | --- |
| `rgb(r, g, b)` | Цвет RGB565 из компонентов 0–255 |
| `clear(color = 0)` | Очистить буфер указанным цветом |
| `color(color)` | Цвет последующих примитивов и текста |
| `pixel(x, y)` | Точка |
| `line(x1, y1, x2, y2)` | Линия |
| `rect(x, y, w, h)`, `fillRect(x, y, w, h)` | Рамка или заполненный прямоугольник |
| `circle(x, y, r)`, `fillCircle(x, y, r)` | Окружность или заполненный круг |
| `text(text, x, y, large = false)` | Однострочный текст встроенным шрифтом, включая русский; до 256 байт, без NUL |
| `image(path, x, y)` | Непрозрачная картинка `.opi`, RGB565, до 320×240 |

Координаты ограничены диапазоном −1024…1024, размеры прямоугольника — 0…1024,
радиус — 0…512. Дробные координаты округляй явно, например `math.floor(x)`.
Текст не переносится; неизвестные шрифту символы пропускаются.
Звука, автоматических спрайтов и PNG/JPEG-декодера в API 1 нет.

Картинку можно экспортировать из графического редактора как **бинарный PPM P6**
и преобразовать без сторонних библиотек:

```powershell
python tools/opd.py image picture.ppm my-game/assets/picture.opi
```

Формат OPI1: четыре байта `OPI1`, `uint16_le width`, `uint16_le height`,
затем `width * height` значений `uint16_le RGB565`, строки сверху вниз.
Картинка читается из Flash при каждом вызове; для частой анимации предпочтительны
примитивы. `assets.read` имеет собственный лимит 64 КиБ, а `graphics.image` читает
изображение построчно и поддерживает полный кадр.

## GPIO и UART для робота

```json
{
  "api": 1,
  "id": "robot-ports",
  "name": "Порты робота",
  "kind": "robot",
  "entry": "main.lua",
  "fps": 20,
  "permissions": {
    "gpio": [16],
    "uart": {"port": 1, "tx": 17, "rx": 18, "baud": 9600}
  }
}
```

Разрешение действует только в пределах текущего бандла. Для нашей AI-S3 N16R8
прошивка выделяет GPIO **1, 2, 16, 17, 18, 21**, только если они перечислены в
манифесте. Политика платы находится в `opd::availablePin` в `src/opd_bundle.cpp`.
Остальные GPIO, включая экран, джойстик, кнопки, USB, Flash/PSRAM и UART0,
приложению недоступны. `kind=game` не может запрашивать порты и не получает
таблицы `opd.gpio` / `opd.uart`.

UART1 может использовать любую пару разных разрешённых политикой выводов.
GPIO и UART не могут занимать один вывод одновременно. Скорость задаётся только
манифестом: **300–115200 бод**, формат **8N1**. Неизвестные типы разрешений,
повторные GPIO, конфликты и недоступные порты отклоняются при проверке бандла.

| Вызов | Действие |
| --- | --- |
| `opd.gpio.mode(pin, mode)` | Режим `input`, `input_pullup`, `input_pulldown`, `output`; новый выход начинается с LOW |
| `opd.gpio.read(pin)` | Логический уровень как `boolean`; предварительно нужен `mode` |
| `opd.gpio.write(pin, boolean)` | Запись только в настроенный `output` |
| `opd.uart.open()` | Открыть UART1 по параметрам манифеста; повторный вызов без изменений |
| `opd.uart.available()` | Число готовых байтов RX |
| `opd.uart.read(n)` | До `n` готовых байтов, `n` от 1 до 256; сразу возвращает бинарную строку, при отсутствии данных — `""` |
| `opd.uart.write(bytes)` | Принять в TX до 256 байт без ожидания освобождения буфера; возвращает фактически принятое количество, возможно 0 |

Остаток после частичной UART-записи надо отправить в следующем `update`.
`write` означает принятие в буфер UART, а не подтверждение от другого устройства.
При закрытии UART принятые данные могут завершить передачу средствами драйвера;
это не протокол аварийной остановки подключённого устройства.

При паузе, выходе и Lua-ошибке прошивка закрывает UART, опускает настроенные
GPIO-выходы в LOW и переводит занятые выводы в `INPUT`. Состояние векторов портов
не восстанавливается автоматически: повтори настройку в `resume`.
В `shutdown` после паузы аппаратные функции запрещены, чтобы не захватить порты снова.
Логика портов — **3,3 В**; двигатель подключается через драйвер, не напрямую к GPIO.
Внешнему контроллеру моторов нужен собственный тайм-аут остановки при потере команд.

## Ограничения исполнения

- Бандл до **2 МиБ**, до **64 файлов**, манифест до **4096 байт**. Общий раздел
  LittleFS около 3,4 МиБ делится с ROM и их сохранениями; список до 32 `.opd`.
- Один Lua-файл — от 1 байта до **64 КиБ**; исполняется только исходный текст,
  загрузка байткода отключена. Синтаксические ошибки показываются при запуске/`require`.
- Lua получает **512 КиБ PSRAM** на VM, строки, таблицы и код. Кадровый буфер
  320×240 RGB565, около 150 КиБ, выделяется отдельно. Стек Arduino loop — 32 КиБ;
  вложенность C-вызовов/парсера Lua ограничена 40.
- На главный файл и каждый обработчик — до **200 000 Lua-инструкций**.
  Hook через каждые 1000 инструкций также проверяет порог **40 мс**. Он прерывает
  бесконечный Lua-цикл, но не может прервать длительную C-функцию или драйвер.
  Это кооперативное исполнение, без гарантий жёсткого реального времени.
- Доступны базовые функции, `math`, `string`, `table`, `utf8`. Нет `io`, `os`,
  `debug`, `package`, `coroutine`, `load`, `loadfile`, `dofile`, `pcall`, `xpcall`,
  `setmetatable`, `getmetatable`, `print`. Защищённые вызовы не могут скрыть
  ошибку бюджета, а пользовательские финализаторы не исполняются при очистке VM.
  Для журнала используй `opd.system.log`.
- В одной оболочке работает одно приложение; подписи бандлов, фоновые службы,
  SPI/I²C/PWM/ADC, сохранения, сеть из Lua и совместимость с Playdate SDK пока
  не входят в API 1.

## Контейнер OPD1

Это простой несжатый контейнер со своей сигнатурой, не ZIP с другим расширением.
Его можно формировать любым инструментом по следующей схеме. Все числа little-endian:

| Порядок | Поле |
| --- | --- |
| 1 | `char[4] magic = "OPD1"` |
| 2 | `uint32 manifest_size` |
| 3 | `uint32 file_count` |
| 4 | `byte[manifest_size]` — JSON UTF-8 без завершающего NUL |
| 5 | Для каждого файла: `uint16 path_size`, `uint32 data_size`, `byte[path_size] path`, `byte[data_size] data` |

Корневой `manifest.json` вынесен в заголовок и не обязателен как запись файла.
Лишние данные после последней записи отклоняются. Сжатия и CRC в OPD1 нет;
структура проверяется при загрузке и перед запуском, содержимое — при использовании.
Прошивка индексирует записи прямо в `.opd` и не распаковывает их в LittleFS.
Упаковщик сортирует файлы и поля JSON, поэтому одна и та же папка даёт одинаковый бандл.

## Проверка реализации

```powershell
.\tools\pio.ps1 run
python -m unittest discover -s tests -v
python tools/check_lua_native.py
```

Последняя команда требует `clang` и `clang++`: собирает настоящие исходники Lua,
`opd_bundle.cpp`, `lua_app.cpp` и `ui_text.cpp`, подменяя только Arduino, экран,
файловую систему и порты. Она проверяет исполнение примеров, модули, бинарные
ассеты, RGB565, события ввода, GPIO/UART, паузу/выход/ошибки, нехватку памяти,
бесконечные циклы, повреждённые бандлы и повторные запуски.
Это проверка на компьютере; физические GPIO/UART, HTTP-загрузка и скорость Lua
на плате требуют отдельной аппаратной проверки. Команды ничего не прошивают.

Основа реализации: [руководство Lua 5.4](https://www.lua.org/manual/5.4/manual.html),
[архив исходников Lua с контрольными суммами](https://www.lua.org/ftp/),
[GPIO ESP32-S3](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/gpio.html).
Исходники Lua и лицензия MIT включены в `lib/Lua`.
