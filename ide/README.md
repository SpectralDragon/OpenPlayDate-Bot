# OpenPlay Studio

## Тема, журнал и медиа

Переключатель **«☀ Светлая / ☾ Тёмная»** справа вверху одновременно меняет
тему приложения, Monaco и редактора блоков. По умолчанию выбирается тема ОС;
ручной выбор сохраняется. Заголовок **«ЖУРНАЛ»** внизу или **Ctrl+J** сворачивает
и раскрывает логи. Свёрнутое состояние сохраняется, сообщения продолжают
накапливаться, ошибки отмечаются цветом счётчика.

В левой панели **«Картинки и музыка»** есть **«+ Картинка»** и **«+ Музыка»**.
Картинки PNG/JPEG/WebP/BMP открываются с предпросмотром и настройкой размера
до 320×240. По умолчанию для костюма предлагается размер до 64×64. Прозрачность
PNG сохраняется с порогом 128. В проекте блоков картинку можно сразу назначить
выбранному персонажу; позже костюм доступен в списке «Вид» и блоке «Стать».
Щелчок по файлу в библиотеке открывает его и предлагает назначить костюм
или вставить вызов `graphics.image` в обычный Lua-проект.

Музыка MP3/WAV/OGG/FLAC декодируется локально, без отправки в облако. Выбери
начальную секунду и фрагмент до 30 секунд. Studio сохраняет WAV PCM, 22050 Гц,
моно, 16 бит; весь `.opd` по-прежнему ограничен 2 МиБ. В проекте блоков можно
сразу добавить событие «Когда игра началась → Играть … по кругу». Есть категория
«Музыка» с блоками запуска и остановки; одновременно звучит одна дорожка.
Системная пауза, продолжение, остановка и ошибки игры управляют её звуком.
В библиотеке доступно прослушивание. **Текущая физическая консоль не имеет
подключённого аудиовыхода; звук воспроизводится в IDE и симуляторе.**

Ассеты сохраняются в `assets/*.opi` и `assets/*.wav`, их названия — в скрытом
`.openplay-media.json`. Размер/число файлов проверяются до принятия импорта;
неудачный импорт удаляет только свой новый файл. OPI2 с прозрачностью требует
обновлённой прошивки; Studio проверяет её поддержку перед отправкой.
Проекты прежней версии блоков обновляются при открытии, только если `main.lua`
точно совпадает с прежним генератором. Ручные изменения не перезаписываются.

`npm run test:media-ui` проверяет темы и сохранение настроек, журнал, настоящий
импорт PNG/WAV, прозрачный костюм в Lua VM, воспроизведение/паузу/остановку
музыки и повторное открытие. Для portable-сборки: `node test/media-ui.cjs --packaged`.

## Игры из блоков

Кнопка **«✦ Игра из блоков»** создаёт отдельный проект «Котик и звёзды».
Стрелки или джойстик двигают котика; пойманная звезда добавляет очко; A меняет
цвет котика на полсекунды. Это наша система для OpenPlay на основе Blockly 13.4,
со своим набором блоков и компилятором в Lua. Проекты Scratch `.sb3` не импортируются.

Слева выбирается персонаж, сверху — его имя, вид, цвет, размер и начальные X/Y.
Можно добавить до 12 героев. В палитре есть события, движение, управление,
внешность и очки. Перетаскивай блоки и соединяй их внутри жёлтого события.
**«↶ Отменить» / «↷ Вернуть»** отменяют и возвращают изменения цепочек текущего
персонажа. Свободный блок нужно присоединить к событию перед сборкой.

**F5** сохраняет блоки, создаёт Lua и запускает настоящий симулятор;
**«На консоль» / F6** использует ту же сборку для загрузки по LAN.
**«Собрать .opd»** экспортирует готовую игру. Во вкладке **Lua** можно посмотреть
сгенерированный код; он доступен только для чтения. Обратного перевода Lua в блоки нет.

Исходник блоков хранится в скрытом `.openplay-blocks.json` рядом с `manifest.json`
и `main.lua`. Переноси всю папку проекта, включая скрытый файл. В `.opd` попадает
только исполняемый Lua и обычные ассеты; редакторские блоки остаются на компьютере.
Сохранение проверяет изменения обоих файлов, сделанные другой программой;
сборка отклоняет рассинхронизированные блоки и Lua.

Каждое событие — отдельная цепочка. `Ждать` приостанавливает только её; остальные
герои продолжают работать. `Всё время` уступает управление после каждого прохода.
Повторы ограничены общим бюджетом операций на кадр, без Lua-корутин или блокирующих
циклов. Новое нажатие не перезапускает ещё работающую цепочку той же кнопки.
Общие очки отображаются сверху; касание проверяется по ограничивающим квадратам
двух видимых персонажей. Рисование костюмов внутри Studio, произвольные
переменные и редактирование блоков ИИ-агентом в эту версию не входят. ACP-помощник
продолжает работать с обычными Lua-проектами.

Проверки: `npm test` включает выполнение сгенерированных игр в Lua VM прошивки,
параллельные ожидания, вложенные повторы, кнопки, касания, бюджет и защиту файлов.
`npm run test:blocks-ui` проверяет настоящее перетаскивание, undo/redo, сохранение
и открытие, симулятор, LAN через тестовую консоль, закрытие с изменениями и размер
1080×720. Для готовой сборки: `node test/blocks-ui.cjs --packaged`.

Electron IDE для наших Lua-программ: редактор Monaco, симулятор 320×240,
виртуальные кнопки, консоль и сборка `.opd`. Интерфейс на русском.

## Игры с голосовым ИИ-помощником

Нажми **Помощник · ACP** в верхней панели. Можно написать идею игры или
изменение существующей: «Сделай игру, где котик ловит звёзды». Нажми **Сделать**
(или Ctrl+Enter в поле идеи). Агент учитывает детскую речь и неполные описания,
использует справочник нашего Lua API, редактирует рабочую копию проекта и
проверяет минимум пять кадров в настоящем Lua-симуляторе. При ошибке он делает
до двух попыток исправления. Это проверка запуска, а не полное прохождение игры.

После работы появится просмотр изменений: слева твой код, справа новый.
**Применить и играть** применяет результат и запускает симулятор. **Оставить
мой код** отклоняет результат. Последнее применение можно отменить кнопкой
**Отменить изменения агента** в панели помощника до закрытия приложения.
Если проект параллельно изменён другой программой, применение или отмена
останавливаются, чтобы не затереть изменения. Нажатие **Остановить** отменяет
текущий запрос. На физическую консоль игра отправляется обычной кнопкой F6.

По умолчанию используется встроенный адаптер **Codex ACP** с существующим
входом в Codex. Если входа нет, открой **Настройки и вход → Войти в Codex**.
Учитываются доступ и лимиты твоего аккаунта. Другой ACP-совместимый сервер
можно подключить там же, указав абсолютный путь к доверенному `.exe` или
Node.js-скрипту и аргументы в виде JSON-массива. Команды через shell не
собираются. ACP-сервер запускается в отдельном процессе. Запросы дополнительных
разрешений показываются в панели; доступны решения для одного действия.

Для голоса добавь **OpenAI API-ключ** в настройках помощника — не в Lua-файлы
и не в чат. Ключ сохраняется с помощью системного шифрования Electron
`safeStorage` (DPAPI на Windows), не возвращается в renderer и не передаётся
ACP-агенту через настройки. Можно также задать `OPENPLAY_VOICE_API_KEY` или
`OPENAI_API_KEY` в окружении запуска; сохранённый ключ имеет приоритет.
API распознавания оплачивается отдельно от входа/подписки Codex.

Нажми микрофон, расскажи идею, нажми ещё раз. Максимальная запись — 60 секунд,
до 8 МиБ. После остановки запись WebM отправляется в OpenAI
`/v1/audio/transcriptions`, модель `gpt-4o-mini-transcribe`, русский язык.
Распознанный текст появится в поле: его можно исправить, затем нажать **Сделать**.
Автоматической отправки распознанной команды агенту нет. Микрофон выключается
после записи/закрытия окна; постоянного прослушивания нет. Галочка **Читать
ответ** использует системный синтез речи, по возможности русский голос.
Если системный голос не установлен, ответ остаётся доступен текстом.

Подключение ACP и генерация кода используют возможности/авторизацию выбранного
агента; запись голоса — отдельный API. Копия проекта не является полноценной
изоляцией неизвестного стороннего ACP-сервера: выбирай доверенного агента.
Встроенный Codex запускается с режимом `workspace-write`, без автоматического
одобрения расширенных разрешений. Код проекта и переданный справочник уходят
выбранному кодинг-агенту; аудио отправляется в OpenAI только для распознавания.

Источники протокола и голосового API:
[Agent Client Protocol](https://agentclientprotocol.com/protocol/v1/overview),
[Codex ACP](https://github.com/agentclientprotocol/codex-acp),
[OpenAI speech-to-text](https://developers.openai.com/api/docs/guides/speech-to-text).

**Загрузка по локальной сети:** Studio умеет найти консоль, собрать программу,
отправить её по Wi-Fi и сразу запустить. Открывать браузер и сохранять `.opd`
вручную для этого не нужно.

## Открыть мастерскую

Дважды нажми `Start-OpenPlay-Studio.cmd` в корне репозитория. Если уже собрана
переносимая версия, она откроется сразу. Иначе скрипт установит npm-зависимости
и соберёт симулятор при первом запуске.

Для запуска из исходников нужны Node.js **22.12+**, Python 3 и **clang/clang++**
(LLVM; также подходит установленный Windows Swift toolchain с LLVM).
Заголовки ArduinoJson берутся из зависимостей PlatformIO этого репозитория:
при их отсутствии выполни `tools/pio.ps1 run` из корня один раз.

```powershell
cd ide
npm install
npm run build:native
npm start
```

Переносимая Windows-сборка после `npm run package` находится в
`ide/dist/OpenPlay-Studio-win32-x64/OpenPlay-Studio.exe`.
Для неё Node.js, Python, компилятор и плата уже не нужны. При переносе копируй
**всю папку** `OpenPlay-Studio-win32-x64`, включая DLL и `resources`.
Сборка предназначена для Windows x64; подпись приложения не настроена.

## Первая игра

1. При первом запуске автоматически открывается **«Прыгучий шарик»**.
   Это рабочая копия в каталоге данных приложения; исходный пример не меняется.
2. Измени `main.lua`, нажми **Запустить** или **F5**. Изменённые файлы сохранятся.
3. Нажми на экран симулятора: **стрелки** двигают джойстик, **Z** — A,
   **X** — B, **Enter** — нажатие джойстика. Можно нажимать кнопки мышью.
   Удержание Enter 0,7 секунды ставит программу на паузу.
4. **Пауза** останавливает приложение; кнопка **Один кадр** помогает наблюдать
   движение по кадрам. Продолжение вызывает обработчик `resume`.
5. **Собрать .opd** сохраняет бандл вне папки исходников. Загрузи его через
   Wi-Fi на страницу консоли, затем открой из раздела Lua-программ.

## Собрать и отправить на консоль

1. Один раз обнови прошивку консоли из этого репозитория: в старой версии
   приём работал только при открытой точке доступа. Обычная прошивка приложения
   сохраняет настройки Wi-Fi, игры и сохранения.
2. Подключи консоль и компьютер к одной домашней сети. IP консоли виден в
   **Настройки → Wi-Fi**.
3. Studio автоматически найдёт устройство в блоке **Настоящая консоль**.
   Для повторного поиска нажми значок обновления. Если консолей несколько,
   выбери нужную из списка.
4. Нажми **Собрать и отправить** или **F6**. Studio сохранит код, соберёт
   OPD1, отправит его и дождётся подтверждения запуска на устройстве.
5. Для следующей версии снова нажми F6. Работающая Lua-программа закроется,
   её порты освободятся, после загрузки запустится новая версия.

Поиск не сканирует всю подсеть: используется UDP-запрос и проверка HTTP API.
Если роутер или брандмауэр блокирует поиск, открой **Указать адрес вручную**,
введи IP консоли и нажми **Подключить**. Studio запомнит этот адрес.
Прямое подключение к точке `OpenPlay` по `192.168.4.1` тоже поддерживается.
При старой прошивке, недоступном устройстве, нехватке Flash или ошибке Lua
причина появится под кнопкой и в журнале. Успех означает подтверждённую
запись бандла и успешное выполнение главного файла/`init`; ошибки последующих
кадров уже обрабатываются консолью.

Во время Game Boy радио приостановлено: выйди из игры перед загрузкой.
Сеть должна разрешать связь между клиентами; гостевой Wi-Fi с изоляцией
устройств не подходит. Протокол предназначен для доверенной локальной сети:
передача идёт по HTTP, без шифрования и отдельного подтверждения на устройстве.

**Новый проект** создаёт копию игры в новой папке. **Проект для робота** создаёт
пример GPIO/UART. **Открыть проект** принимает папку с `manifest.json`.
Кнопка `+` над файлами создаёт Lua-модуль или текстовый ассет, включая вложенные
папки (`assets/story.txt`). Бинарные `.opi` добавляй в папку проекта обычным
файловым менеджером, затем открой проект заново.

Вкладки сохраняют свои изменения и позицию курсора. При закрытии приложения,
вкладки или смене проекта есть выбор: сохранить, не сохранять или вернуться.
Если файл изменился в другой программе, сохранение остановится с сообщением:
открой проект заново для чтения новой версии; при необходимости заранее скопируй
свой изменённый код. Ошибки Lua показаны в консоли; нажми на сообщение со строкой,
чтобы перейти к коду. **F1** открывает справочник встроенного API.

| Клавиши | Действие |
| --- | --- |
| F5 | Сохранить и запустить заново |
| F6 | Сохранить, собрать, загрузить и запустить на настоящей консоли |
| Shift+F5 | Остановить |
| Ctrl+S | Сохранить все открытые изменённые файлы |
| Ctrl+O | Открыть проект |
| Ctrl+Shift+B | Собрать `.opd` |
| F1 | Справочник API |

Клавиши консоли работают только после фокусировки её экрана. В редакторе
стрелки и буквы продолжают редактировать код. Потеря фокуса отпускает кнопки.

## Симуляция робота

Открой блок **Виртуальные порты**. Для настроенного GPIO-входа кнопка меняет
уровень `0/1`; на выходе отображается уровень, заданный программой.
`input_pullup` начинается с HIGH, `input_pulldown` — с LOW.
Поле **UART1 RX** передаёт UTF-8 текст; передачи TX появляются в журнале.
Порты доступны только с разрешениями манифеста, как на устройстве.
Пауза освобождает порты; `resume` должен настроить их заново.
Пошаговый запуск вызывает `resume → update/draw → pause` на каждый шаг.
UART моделирует небольшой передающий буфер; программа должна учитывать
частичную запись так же, как в примере `robot-ports`.

## Что именно эмулируется

Симулятор **запускает настоящий Lua 5.4.9 из прошивки**, `src/lua_app.cpp`,
`src/opd_bundle.cpp` и русский растровый шрифт `src/ui_text.cpp`.
Сохраняются лимит памяти VM 512 КиБ, бюджет инструкций, загрузка модулей,
ассетов и обработчики жизненного цикла. Запуск идёт в отдельном процессе.
Растровый адаптер воспроизводит примитивы RGB565 и экран 320×240;
частота в панели — частота полученных кадров, а не замер ESP32.

Это симулятор **Lua-приложений API 1**, а не эмуляция процессора ESP32,
всей оболочки OS, Wi-Fi, электрических сигналов или времени работы железа.
Меню OS, Game Boy и игры Playdate `.pdx` здесь не запускаются.
GPIO/UART виртуальные, реальные COM-порты не открываются.
Ограничение 40 мс внутри Lua-hook использует часы симуляции; дополнительный
watchdog в Electron завершает неответивший процесс за 3 секунды.
Реальную производительность, питание и оборудование проверяй на консоли.

## Сборка и проверки

```powershell
cd ide
npm run build:native
npm test
npm run test:ui
npm run package
npm run test:packaged
npm run test:agent-ui
npm run test:acp
```

`npm test` сравнивает OPD1 побайтно с Python SDK, проверяет пути и лимиты,
запускает настоящий Lua с графикой, модулями, ассетами и кнопками, проверяет
GPIO/UART, паузу, синтаксические ошибки и бесконечные циклы.
Сетевые тесты проверяют UDP-поиск, HTTP-идентификацию, точную отправку бинарного
бандла, смену устройства по тому же адресу и отрицательные ответы консоли.
`npm run test:ui` открывает изолированный тестовый экземпляр Electron,
проверяет редактор, кадры, шаг, клавиатуру и восстановление после Lua-ошибки.
Снимки сохраняются в `ide/test/artifacts`.

Тесты агента используют настоящий ACP JSON-RPC через stdio с тестовым сервером,
проверяют рабочую копию, доступ к файлам, разрешения, отмену, исправление Lua,
применение и откат. `test:agent-ui` дополнительно проверяет шифрование ключа,
настоящую запись WebM с тестового микрофона Electron, просмотр изменений и
запуск. Распознавание речи в тесте заменено ответом без внешнего API-запроса.
`test:acp` только подключается к настоящему Codex ACP и создаёт сессию, не
отправляя запрос модели. `node test/acp-live.cjs` — явная дополнительная проверка
генерации с расходованием лимита аккаунта Codex; в обычные тесты не включена.

Проверено с настоящим Codex ACP: по текстовой просьбе агент создал игру про
котика и звёздочку, изменил Lua, манифест и подсказку; полученный бандл прошёл
проверку пяти кадров. Облачное распознавание голоса без пользовательского
API-ключа не запускалось; запись WebM, запрос к API и обработка ответа покрыты
тестами с подменой сетевого ответа.

Настройки содержат только последний проект; они лежат в `studio.json`
в каталоге `app.getPath('userData')`. Renderer работает в sandbox с
`contextIsolation`, без Node.js; разрешённые операции доступны через preload.
Приложение не требует интернета после установки/сборки.
